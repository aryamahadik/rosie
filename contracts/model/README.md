### Verbs and what code checks (arch 03 lines 183 to 187)

- `choose(question, choice, fields)` takes a choice of kind `option`, `hub` or `whichBooking`; `question` is the choice's own `question` (the open question's id, the hub's step, or the booking a which-booking choice stands for). `enter(choice, fields)` takes `door`, `anytime` or `searchEntry`. Each field carries its value and the exact words it comes from; code re-parses every value from its words (limit 6, arch 06 line 309).
- A bare "2", "ok" or reaction counts only when it clearly answers the one open question (S13-24 rule 8): `decide-bare-2.json`. A poll vote answers its own poll: `decide-poll-vote.json`, where the vote's text `words` are the option's words as sent. A tapback is never a yes; where a pick is needed the reads agree on `ask`: `decide-tapback-asks-which.json`.
- `hand_off` (decide's and the planner's) carries `about`, a closed list: `ownerOrStaff`, a report about the owner or staff, goes to Rosie's team that day, never the person named; `other` goes to the owner in text hours, then Rosie's team after 2 days (arch 06 line 329; S13-29 rule 58; S13-27 rule 36's note "If it's about the owner or staff ... only Rosie's team gets it"; S11-19). The hand-off code (C-104) routes on it, never on the reason's words: `decide-hand-off.json` (other), `decide-hand-off-owner-or-staff.json` and `planner-hand-off.json` (ownerOrStaff).
- Two reads must agree on every choice and every field value. On a disagreement, an unmapped part or a value that fails its words, the one Sonnet re-read runs; still unclear, the part ends in one question and nothing changes for it (`outcome: "oneQuestion"`); parts both reads agree on go ahead (arch 02 line 119; Q-41's default: the re-read runs before the question): `decide-reads-disagree.json`.

Each danger word code matched (`safetyResult.dangerWords`) names its `list` (general or plugin) and its `kind`, so the handle actor (C-047, C-174) picks the safety line with no read: "a danger-word match counts as Unsure and gets the safety line (988 and 911 for self-harm words, else 911)". `selfHarm` marks words about suicide, self-harm or a mental health crisis (A3-25: "Words about suicide, self-harm or a mental health crisis get the 988 line at once"; A3-22's general check names self-harm, and its "Crisis words" means suicide, self-harm or a mental health crisis); every other danger word is `other` (danger to life, fire, gas, a medical emergency: A3-22; a trade's own words, arch 06 line 283). No source lists the words themselves (open gaps).

## Model-facing schemas: the structured-outputs subset (J-02 open)

`decideRead`, `safetyRead` and `plannerOutput` are what the model answers in, so each is written inside the JSON Schema subset the model API's structured outputs accept (02-contracts section 2 item 7). `contracts/scripts/structured-subset-lint.mjs` checks them on every `npm run contracts:check`, following Anthropic's structured-outputs documentation as T-360 read it on 2026-11-07:

1. **External `$ref` is refused**, so the AI gateway sends each schema **bundled**: every `$ref` resolved and its target copied into the schema's own `$defs` (`bundleSchema()` in the lint is that bundling). This contract file keeps its relative `$ref`s; the lint checks the bundled form, and its test shows the bundled forms accept and refuse every K-02 fixture exactly as the contract does.
2. **Per-request limits** across all structured schemas and strict tools in one request: 24 optional properties, 16 parameters with a union type (`anyOf`, or a type array), 20 strict tools; a schema too complex to compile is a 400. One request carries one of these schemas. Every property here is required: decide read 0 optional and 2 unions, safety read 0 and 0, planner 0 and 1.
3. **Schemas stay static** (compiled grammars are cached for 24 hours): never an enum of a turn's option ids. A choice id is a plain string in the output and is checked in code (`optionOffered`, below).
4. **Left out:** recursive schemas, number limits, string-length limits, array limits other than `minItems` 0 or 1, complex enum values, and any `additionalProperties` other than false. "Non-empty" is the pattern `\S` (`nonEmptyText`). **Allowed:** local `$ref` and `$defs`, `anyOf`, `allOf` (not with `$ref`), `const`, enums of scalars, `required`, simple `pattern`, and the formats date-time, time, date, duration, email, hostname, uri, ipv4, ipv6, uuid (none used here).
5. **For the AI gateway (C-121):** a refusal is HTTP 200 with `stop_reason` `"refusal"`, and its output may not match the schema; `stop_reason` `"max_tokens"` means the output may be incomplete. Both are a failed read, never a verdict: the gateway's retry and outage rules apply (arch 06 line 293), and for the safety read the 4 s timeout marker (arch 02 line 111).

The context and the stage results are not model output: they may use any 2020-12 keyword, so the context holds the frontier to at most 60 choices and the decide result to 2 or 3 reads. **J-02 stays open:** the live structured-output check on claude-haiku-5-5 and claude-sonnet-5-5 runs as smoke-size calls only (DL-027, Q-20) once the lead schedules it; until then the subset is the documented one, linted.

## Named rules (what the schema refuses, and what the rules refuse)

Two refusals state a rule across two documents, the context and the decide result, that one JSON Schema cannot express. `model.rules.mjs` states each by name; a fixture of `$defs/contextAndDecide` names its rule in `fixtures/index.json` (`"rule"`), must pass the schema first, and is then refused by that rule alone (`contracts/scripts/check-fixtures.mjs`).

| `refuse-unknown-verb.json`        | the schema (`decideRead`)      | a verb that is none of the eight                                                                                                                                                              |
| `refuse-value-without-words.json` | the schema (`decideRead`)      | a field whose words are empty                                                                                                                                                                 |
| `refuse-planner-books.json`       | the schema (`plannerOutput`)   | a planner verb that is none of the five                                                                                                                                                       |

At runtime the same rules are the gate's (C-080 refuses a choice not offered, arch 06 line 333) and code's quote check (arch 03 line 185: "code confirms the quote and re-parses every value from its words"); the rules file states them in the contract and does not implement them. The frozen-contract guard covers the schema, fixtures and index of v1, but not `model.rules.mjs` (it guards `.json` files whose name carries a version): a later version adds rules under new names and never changes these two.

## Stakes (arch 01 line 79)

"High when the target question, or the first read's pick, can charge, refund, book, move or cancel. Otherwise low." Each choice carries `stakes` and, when high, `stakesFrom`, its reasons; the schema refuses a high choice without a reason and a low one with any. K-01 v1 has no stakes field (its open gap), so the frontier builder (C-075) derives it from the bundle:

- **high** when the choice's walk (its branch, then the steps it walks to before it stops at the first step that asks someone, waits or ends the journey: arch 03 line 191) holds an effect (K-01 `effect.kind`) of `charge`, `refund` or `calendarWrite`; or a `recordWrite` of the gives key `booked` (given in section 6) or of a section 5 money key (`money_before`, `card_saved`, `deposit_paid`, `paid_full`: `A-keys.md`, `B-keys.md`); or the choice is the any-time row `cancel` or `move`;
- every option of an open question is high when any one of its options is high (`question`: "the target question ... can");
- a choice the builder cannot walk is high (`unknown`), the safer route: Sonnet reads first, and any difference asks one question (arch 06 line 287);
- otherwise low. The turn's stakes (`decideResult.stakes`) is high when the target question, or the first read's pick, is high.

This is a default, not a source: no source lists which record writes book, move or cancel (open gaps).

## v1.2 (T-1157): an unmapped turn's end

**Why** (contract-change skill item 2): CQ-162 (a), raised by T-369's builder and met first by T-370 (its builder's question a; DL-342). A read is unmapped when the model answers but the AI layer's validator refuses the answer: it is not a `decideRead`, or a named rule fails it against the turn's context (arch 02 line 119; arch 06 line 289: "Reads disagree, a part is unmapped, or a value fails its words | Sonnet re-reads, once per turn | Still unclear: one question; nothing changes for that part"). T-370 re-reads such a turn once inside the AI layer, and a turn still unmapped ends in one question with nothing changed (CQ-162 (a)'s default; T-370 default 5). But v1's `decideResult` holds only K-02 reads, so that end had no K-02 shape: the AI layer answers it with no result, the turn loop (T-558) answers `{error: "unmapped"}`, and the run ends without the question, is run again, then parked (T-370's question a). **Kind:** additive, a minor version. `model.v1.2.schema.json` holds every v1.1 definition under its own name: the unchanged ones by `$ref` to `model.v1.1.schema.json`, which stays as it is; `refusedRead` is new; `decideResult` takes a refused read and the end; `contextAndDecide` carries v1.2's decide result. A result with no refused read is exactly v1's, so every v1 and v1.1 payload is a v1.2 payload (`npm run contracts:check` checks every accepted earlier fixture against v1.2). The model-facing definitions are v1's: the model never writes a refused read or the end; code records them (the card's "Not here": the AI layer's structured-output schemas).

**Not here:** decide's code for it (T-1158); the turn loop's ports (C-046) and the gate (C-080), each in its own task ("Who reads v1.2"); the re-read after meaning search (T-1159); photo reading, now v1.3.

### What v1.2 adds

- **`refusedRead`**: one read the AI layer's validator refused, in its place among `decideResult.reads` (first, check or reread), with the model that answered and `refused.unmappedParts`, the parts of the refused answer that failed (0-based, in the answer's own order; empty when the answer failed as a whole rather than part by part). It holds no `output`: the refused answer never reaches the gate, and the named rules read only a read's output (`model.rules.mjs`, `partsOf`), so they skip it and no named rule is added.
- **`decideResult.end`**, `"oneQuestion"`: set on an unmapped turn's end and only there. The whole turn ends in one question (one for the turn, not one per part) and nothing changes for any part, agreed parts included.
- **What the schema refuses** (`dependentSchemas`): a turn with a refused read and no `end`; a part that goes (`outcome: "go"`) on a turn with a refused read (`refuse-go-with-refused-read.json`); `end` on a turn with no refused read, or before the re-read (`reread` false). `parts` may be empty on that end alone; every other result has at least one part, as in v1.
- **What code checks** (the contract test, below): `agreed`, `language` and the kept parts follow defaults 14 and 15; each index in `unmappedParts` is a part of the refused answer, which the result does not hold.

### Defaults (T-1157), numbered after T-1142's

12. **Any refused read ends the whole turn in one question.** On a turn with a refused read, the one re-read runs (Q-41: the re-read before the one question), and then the turn ends in one question with nothing changed, agreed parts included, even when the check read and the re-read agree (CQ-162 (a)'s default, "a turn still unmapped ends in one question with nothing changed", as T-370 built it: default 5, "Any refused read (unmapped turn, or a refused re-read) ends the whole turn in one question with nothing changed, agreed parts included"). A ruling that a K-02 re-read settles an unmapped turn would let parts go again: a later minor version that only relaxes this rule.
13. **A refused read holds labels only.** Its model, its role and the indexes of its unmapped parts; never the refused answer, its quotes or words, or the validator's problem lines, which stay in the AI layer (T-369's `DecideReadRefused`: "Problems name fields, parts and rules, never words"; T-558's notes: spans carry labels only). So nothing the gate would refuse reaches it.
14. **The parts kept on that end:** the parts of the turn's last K-02 read (the re-read's, else the check read's, else the first read's), in its order, each with `outcome: "oneQuestion"`, kept for the trace and the question as v1's `resultPart` keeps a oneQuestion part ("For oneQuestion, part is the last read's verb, kept for the trace and the question"; T-370's `unclear`: "the re-read's part there, or the last read's that has one"); none when every read was refused.
15. **`agreed` and `language` with a refused read.** A refused read agrees with nothing and reports no language. `agreed` is false when the first or check read was refused. `language` is the one two K-02 reads of the turn agree on (the first and check reads', or the re-read's when it is one of theirs: T-370 default 4), else null (CQ-07's default: the two decide reads, which must agree); a null language falls back for the question as it does on any turn (arch 06 line 341).
