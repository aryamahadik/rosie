### The event log (arch 09 lines 457, 492)

- **Every write appends a row; none is ever edited.** So no row's `table_name` is `event_log`: the log never records a change to itself, because none happens (`refuse-event-update.json`). K-04 enforces it in the database (insert and select only on `event_log`; K-04 README rule 5).
- **Columns.** The row is K-04 v1's `event_log` row as JSON. The not-null columns (`id`, `at`, `trace_id`, `actor_kind`, `kind`) are required; a nullable column may be left out, meaning null. The schema repeats K-04's checks: a person actor names the person; sealed values name the person whose key seals them; every row names its turn or its job. K-04 v1's three seed rows (`seed-event-log.json`) pass `eventLogRow` (checked 2026-11-07).
- **Who.** `actor_kind` is person, rosie, job or provider. A person's own act (an answer, a STOP) is the person's; what the commit writes because of it is Rosie's, with the person's answer as `approved_by`.
- **What.** `kind` is `<subject>.<move>` from the closed list below; the touched row is `table_name` and `row_id`. A phone row is named by its handle id (`phones.handle_id`, unique in K-04), never by its number.
- **Old and new.** `old_values` and `new_values` hold the plain fields that changed, keyed by column. Private values (a phone number, an email address, words a person wrote, a private note) are left out and go into `sealed_values`, sealed under one person's key (`sealed_for_person_id`); a write touching two people's private values writes two rows (K-04). The schema refuses an E.164 number or an email address in a plain value and in the items of a list or object it holds (two levels: a recursive definition breaks the generated types, so anything nested deeper is the contract test's check); words are the writer's duty and the contract test's check.
- **Why** names at least one of: the step, the choice (its id, or its label as the bundle writes it), a limit and its outcome, the safe default, the outage step, or the provider event behind it.
- **Approved by** is the exact yes: an `answer` (question, option, inbound event), a `consentRow` (its id in K-29), or the `ownerYes` (owner or admin, question, option, event).
- **Proofs** survive a deleted key: the sha256 of the person's own words and the words Rosie showed them, when they were delivered, with the question or K-01 fixed line they were. When a key is deleted the sealed values can never be read again; the proofs stay (`event-erased-person.json`).

### Traces (arch 10 line 548; tour lines 656 to 658; BP 5.5)

- **One trace id from webhook to delivery receipt.** A text's webhook opens one; so do a page request, an Agent API request, a clock firing, the minute sweep, a Stripe or calendar webhook and reconciliation (`opened_by`; CQ-06). When a turn batches several texts it carries the first text's trace id and lists the others in `joined_trace_ids`, and each other text's trace ends at its batch span with outcome `joinedTurn` (CQ-06; K-04 `turns.trace_id`, `joined_trace_ids`).
- **A span is one log line** (ADR-009): its fields sit beside ADR-009's `level`, `msg` ("span"), `trace_id`, `environment` and `version`. Workers Logs indexes the fields, so a trace is read by filtering on `trace_id` and ordering by `seq`.
- **Each span carries** the trace id, its own id, its place (`seq`), the hop, when it started and how long it took (`at`, `ms`), the bundle id, the turn id (null before the batch closes, and for a job), the job id for a job, the inbound event id before a turn exists, a handle reference, the business when known, for an outside call the provider, the call and its attempt, what it got and what it decided, the limits it ran, the rows it wrote, its model calls, and its outcome or error code.
- **Outside calls** (`provider`, `call`, `attempt`; arch 02 diagram line 105; arch 10 lines 540, 542). `provider` is the vendor from the closed list (linq, resend, stripe, google_calendar, microsoft_calendar, google_places, geo, r2, anthropic), never free text in `got` or `decided`, which refuse a `provider` key. `call` is the port call by its port contract's name (`sendPart`, `calendarUpdate`, `search`, `geocode`, `serverWrite` …). `attempt` is the try, from 1: a send's try (the last part of K-07's idempotency key row/part/try, each after any Retry-After), an effect's try on its one idempotency key (at most 5 in 10 minutes, then that service's outage row), another job's try (at most 5, then the dead-letter queue). All three are required on `effectRun`, `portCall` and a `dispatch` that sends (not one that ends dropped, held or refused); `provider` alone is required on `receive`, `providerAccepted`, `delivered` and `providerWebhook`. Model calls keep their own `model_calls` list.
- **Never the raw number or words.** The handle reference is K-04's handle id. What a hop got or decided is named values: a count, a yes or no, or a label (an id, a step, an option id, a code, an outcome name: letters, digits and `_ . : / # -`, never spaces, `+` or `@`, never a long run of digits). So the schema refuses a phone number, an email address or a person's words in a span (`refuse-raw-phone-in-span.json`, `refuse-raw-text-in-span.json`); full detail lives only in the sealed traces in R2 (arch 02 diagram line 105).
- **Model calls** (`model_calls`, required on the safety read, decide, re-read, planner and compose hops): the model id, which of the bundle's two models, what the call was for, input tokens, cached tokens, cache-write tokens, output tokens, the cost in micro-dollars, the time, and the outcome. A refusal or a cut-off output is `failed`, a failed read and never a verdict (K-02 v1 README).
- **The gate's limits** (`limits`, required on the gate): each of limits 1 to 6 with pass, fail or notChecked and, on a fail, its own outcome; limit 7 rides the fill-and-checks and rewrite spans, limit 8 the dispatch span.

### Measures read from traces

- **Reply time** (`replyTime`): from the arrival of the turn's last text (the start of its `receive` span) to Linq accepting the reply's first part (the `providerAccepted` span of the first outbox row's part 1), the re-read inside it and a rewrite on top (Q-41's default; CQ-06's default). It is read per bundle, for the p50 ≤ 10 s and p95 ≤ 18 s targets and the canary's rollback on p95 over 18 s (arch 04 line 229; arch 10 line 552).
- **The hourly hard-invariant checks** (`invariantRun`): no charge without a bound yes, no double booking, no text after STOP beyond what the stopped flag allows; each with its breach count, the trace id of each breach for the page and the rollback alert, and the bundles in force (arch 08 lines 427, 445; BP 5.4).
- **Cost** is summed from the spans' model calls; what counts as a completed booking for the $0.16 gate is CQ-12's.

### The export (arch 10 line 544)

The event log goes to R2 Parquet so reports and evals never touch the primary. An export row (`exportRow`) is the stored row unchanged, sealed values still sealed (the export never opens them), with `sealed_key` saying whether the person's key was held or already erased when it was read, and `exported_at`. Deleting a key erases the sealed values in the export too; the proofs' hashes and words stay.

## Defaults used (T-017)

1. **Every span carries a bundle id** (02-contracts K-08: "Each span carries the bundle id"): the turn's pinned bundle, or for a hop before the pin or outside a turn the active bundle id read at that moment (arch 10 line 536). The actor already reads the bundle for the safety read's prompt and danger words; the gateway's `receive` and `scrub` spans carry the active bundle id it reads with the event. Proposed for QUESTIONS.md (below).
2. **Snake_case field names** throughout, as K-04's columns and ADR-009's `trace_id` spell them.
3. **A phone row is named by its handle id** in `row_id` and `rows`, never by its number (`phones.handle_id` is unique in K-04), so no raw number enters the log in plain or a trace.
4. **Plain values hold no E.164 number and no email address**, checked two levels deep; a person's words go sealed (arch 09 line 492; arch 10 line 516).
5. **A proof's hash** is the plain sha256, in lowercase hex, of the person's own words as UTF-8.
6. **`cache_write_tokens`** beside the tokens and cached tokens the plan names, since cache writes are priced apart and the cost must be checkable.
7. **Cost in whole micro-dollars** (`cost_micro_usd`): one model call costs well under a cent, below CQ-09's money format of whole cents; the gate's $0.16 is 160000.
8. **The kinds** are `<subject>.<move>`, from K-04 v1's core rows, the commit's writes (K-05 v1 item 1), K-07's effect and provider-event rows and consent rows, with K-04's three seed kinds kept as they are.
9. **A clock firing runs under its job id**, with no turn id (02-contracts K-08: "or a job id for a clock firing"; QUESTIONS.md M2-runtime-ai.4's default: under the firing's own trace id, with no decide reads), since a turn id is a hash of texts' event ids (CQ-09).
10. **The export row** keeps the sealed bytes sealed and says whether the key was held or erased; the export never opens them.
11. **`providerAccepted` is an instant** (`ms` 0) at the moment Linq accepts a part; the `dispatch` span holds the send call's time.
12. **The writes a person's answer causes are Rosie's** (`actor_kind` rosie) with the answer as `approved_by`; the answer itself is the person's.
13. **The vendor is a span field** (`provider`, from the closed list of arch 02 diagram line 105's third-party services), required on every hop that calls out or that a provider's message opens, and never a key of `got` or `decided`, so traces filter by vendor.
14. **`call` is a label and `attempt` counts from 1.** The call names are the port contracts' (K-11 to K-17, frozen F6 to F12, after this one) and K-07's effect kinds, so v1 does not close the list; a closed list per provider, once the ports freeze, is a minor version. `attempt` is the try number the retry rules count (arch 10 lines 540, 542; K-07's row/part/try key); a dispatch that sends nothing (dropped, held, refused at limit 8) carries none.

## Open gaps

- **CQ-06** (a batch's trace id; non-webhook starts; where reply time ends): its default is used throughout; a ruling changes data, not the contract, except a new `opened_by` value (a minor version).
- **Q-41** (how reply time is measured): its default, from the last text's arrival with a rewrite on top.
- **CQ-12** (what counts as a completed booking, and which calls count): the cost meter's rule; the spans carry every call's cost either way.
- **New (the bundle id on gateway spans):** default 1. Whether the gateway reads the active bundle id at receipt, or its two spans carry none and the trace's later spans name it, is for the CTO; the second would make `bundle_id` nullable on `receive` and `scrub`, a breaking change, so it is asked now.
- **New (the cost unit):** default 7; CQ-09 names only cents. The price list itself (where it lives, who updates it) has no source; the cost meter (C-143) reads it.
- **New (proof hashes):** default 5; a plain hash of a short reply such as "STOP" can be guessed back. Whether proofs use a keyed or salted hash (and where that key lives, never in the person's sealing key) is for the CTO, with the security reviewer.
- **New (who may open sealed values):** this contract never opens them; which role, page or job may (the person's own secure page, a dispute) is C-156's and K-21's.
- **New (the export's layout):** the R2 keys, partitions and cadence of the Parquet export wait for K-13 (files port, F8); v1 fixes only the row.
