## What it defines

Linq's paths, headers, field names and codes stay inside the adapter (C-206 to C-209); the fixtures are port-level exchanges. Each call is a definition set under `$defs`: `<call>.request`, `<call>.response`, `<call>.errors`, and `<call>.exchange` (a fixture). Every field's `description` names its source; "arch NN line N" are the lines of `scratch/text/architecture.txt`.

A chat Linq reports as SMS gets words only, with no file and no thread (DL-031; arch 07 line 383: "Files do not reach SMS").

### Outcomes of a send

`accepted`: Linq's message id (null for a tapback and typing dots), for a poll its option ids in the options' order, the chat, the service Linq reports, and when it was accepted (K-08 `providerAccepted`). `failed`, by `kind`, which picks K-07's retry rule:

| `kind`            | Read from                                      | What the dispatcher does (K-07)                                                                  |
| ----------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `optedOut`        | 403 with code 2024                             | Not retried as it was; limit 8 drops a stopped phone (arch 10 line 524; K-07 rule 7)             |
| `mayStillDeliver` | code 4001 or 4006                              | A new key only if no delivery receipt within 1 minute (arch 01 line 65; K-07 rule 2)             |
| `rateLimited`     | 429 (Linq code 1007), with `retryAfterSeconds` | The next try after any Retry-After (arch 10 line 540; K-07 rule 6)                               |
| `refused`         | any other request error, such as 1004 or a 400 | Goes again plain: options typed, a card's bare link, words without their file (arch 07 line 367) |
| `transient`       | a server or network error, or no answer        | K-07 rules 1 and 5 (arch 01 line 65; arch 02 line 125)                                           |

### The double

The Linq double (C-211, test code only) answers `sendPart` and `contactAdd` with any outcome this contract defines, as the test chooses (4001, 4006, 403 with code 2024, a rate limit; added or failed), records every `sendPart` request in order, and makes signed webhooks with `doubleWebhook` (02-contracts K-11 "The double's test hooks"; BP 9.4).

## Defaults used (T-020)

1. **Secret names:** `LINQ_API_TOKEN` (the Nov 5 kit's name) and `LINQ_WEBHOOK_SECRET` (Linq's SDKs' name), until the CTO and the release engineer name them (02-contracts section 2 item 13).
2. **Event types Rosie does not use** (such as `message.read`, `chat.typing_indicator.started`) are verified, answered 200 and dropped (`ignored`); no source names them.
3. **The webhook id is the event id:** `webhookId` (the `webhook-id` header) is what the signature covers, and the parsed event's K-06 `eventId` is the envelope's `event_id`; Linq's documents call both the dedupe key, and the fixtures make them equal. If a live capture shows they differ, the adapter keeps `event_id` as `eventId`.
4. **A tapback and typing dots return no message id** (`providerMessageId` null), since Linq answers "Reaction processed" and 204.
5. **A photo goes on iMessage only,** the one service it was tested on (MC 8: a format not tested gets its test first).
6. **The calendar file travels as its `.ics` text** in the request; the adapter uploads it (row 10) and sends it as a media part with the words.
7. **4001 is `mayStillDeliver`** as arch 01 line 65 says, although Linq's page for 4001 says only "Send the message again": the 1-minute wait for a receipt costs at most a minute.
8. **A link card's preview words** come from the linked page itself (row 10: a link part has only its URL), so K-03's link-card text is not sent; the secure page's own preview gives the business name, or the display name and "your visit" for sensitive work (arch 07 line 381).

## Open gaps

1. **contacts/add (Q-03, CQ-04):** the spike found no documented Linq call that adds a contact to the line. The Nov 5 kit used the Linq command-line tool (`linq contacts add`), and Linq's v2 API has a CRM-style `POST /api/partner/v2/contacts` with another auth header; neither is confirmed as what lets a mobile text the line, nor is the 2008 "recipient not in the allowed list" error's link to it. The port call (`added` or `failed`) is frozen; the adapter's wire mapping waits on Linq support or the CTO (proposed for `QUESTIONS.md`). Until then the double answers it.
2. **Q-52's subscription list:** Linq's vote event is `poll.vote.added`; `poll.updated` reports options someone added to a poll, not a vote (row 9). So the webhook move should add `poll.vote.added` as well as `message.sent`, `message.edited`, `poll.updated`, `poll.vote.removed` and `poll.failed`, and the subscription must use `webhook_version` 2026-02-03, the only one that delivers `message.edited` (row 8). K-06's `pollVote` description names `poll.updated`; the adapter maps `poll.vote.added` to `pollVote` and `poll.updated` to nothing in v1 (an added option reads as typed words when voted for: S13-24 rule 6). For the CTO, at the move.
3. **Linq lifts a 2024 block on any later non-stop text** (row 15), while Rosie's stop holds until START (RULES 4.1b). So after a stopped person texts again, Linq would deliver Rosie's sends without `overrideOptout`; Rosie's own stop flag and limit 8 are what keep them out. Nothing changes in the port; the guard (C-052) and limit 8 must never rely on Linq's block.
4. **T-410's signature helper** checks a hex HMAC under the secret's raw bytes; Linq signs `v1,<base64>` under the base64-decoded `whsec_` key, and its deprecated hex header signs `{timestamp}.{body}` without the id (rows 2, 3). The adapter must decode the key and compare base64, or the shared helper must learn it: a new task for the integrations engineer, outside this card.
5. **Codes other contracts hold as placeholders:** K-07's `429` and `poll.failed` error codes are Linq's `1007` and the poll's own `error.code` (such as `4001`); K-06's `poll-failed.json` has `code` null where Linq gives one. Both contracts already take any code as text, so nothing breaks; the adapter fills Linq's code.
6. **Bold, read receipts, edits, contact files, an SMS channel:** not in v1 (MC 8; DL-012); each a minor version once tested and needed.
7. **Q-44, Q-53:** staging sends only to roster phones (C-210's allow-list in the adapter, not a port field); the roster is `08-needs-from-jay.md`'s.
8. **CQ-11, answered by DL-031:** a chat Linq reports as SMS or RCS gets its reply there, text only (and link cards on RCS); no SMS port.
