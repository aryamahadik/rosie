## What it defines

The calls that own every read and write (arch 02 line 139), "generated from the master's needs and gives keys" (arch 12 line 590). The same calls serve texts, secure pages and outside AIs under the same limits; free text from pages and AIs gets the safety read first (arch 02 line 129); row-level security scopes every call by the caller's business (arch 10 line 546; K-04 v1 rule 4). Every request carries a `caller` (`$defs/caller`): who calls (a turn, a page, an agent, the console, a job, a clock firing, or the handle actor writing on return), the business it runs under, the person it acts for (stated per call as the session's `rosie.person_id`, which K-22's row predicates read: T-031, named in words), the key a repeat is known by, and the trace it joins (K-08).

Every field's `description` names its source (02-contracts section 2 item 4). "arch NN line N" are the lines of `scratch/text/architecture.txt`, as `ops/plan/02-contracts.md` cites them. Frozen contracts are reused by relative `$ref` where a call carries their shapes: K-01 v1 (`stepId`), K-02 v1 (`context`, `text`, `contextAndDecide`, `plannerOutput`, `safetyResult`, `safetyOutcome`, `language`), K-03 v1 (`composeInput`, `rowPlan`, `finalParts`, `checkResult`), K-05 v1 (`turn`, `commitResult`, `rowRef`, `sendClass`, `phoneNumber` and its errors), K-07 v1 (`effectKind`, `rowState`), K-08 v1 (`traceId`, `limitResult`) and the shared formats (`id`, `turnId`, `utc`, `money`). The table parts (K-04 core, K-23, K-24, K-26, K-29, K-33, K-34, K-36, K-37) are table lists, so the calls name their tables, columns and closed lists in words and enums, never by `$ref`. Parts not yet frozen (K-22, K-25, K-27, K-28, K-35, and the ports K-12 to K-16) are named in words only (open gaps).

### In a turn or alone

A turn commits once (arch 02 line 121; arch 10 line 508). So a shared-core call made in a turn (a STOP, a safety outcome, a door, an owner's answer to a hand-off, a staff member's ready text) rides inside `gateAndCommit`: its request in `request.core` (`$defs/coreAction`, with `caller.kind` turn) and its response or error in `response.core` (`$defs/coreResult`). A setup step's write in a turn is the effect code adds for the choice decide picked, and the part's result names the keys it gave (`partResult.gives`). A refused core action stops only itself. A call made alone (by a page, an agent, the console, a job or a clock firing with no handle) commits once under `caller.requestId`, which waits for K-05's commit with no turn (CQ-44's default). An exchange whose `caller.kind` is turn and whose call is not `gateAndCommit` shows a core action or a step's write as it rides inside a turn's commit: the same request and result, which the mock answers the same way.

## Named rules (`tool-api.rules.mjs`)

What an exchange states that one JSON Schema cannot check across its parts. `npm run contracts:check` runs the rule an index entry names on a fixture that has passed its schema; QA's contract test and the mock read the same statements. Rules are only ever added.

- **`statedOutcome`:** a gate exchange whose `given.stated` names a limit stops exactly one part, by that limit, with that kind of outcome and that action, and logs that limit as failed with that action on the part's limits (02-contracts K-09 "Contract test": each limit fixture gives its stated outcome).
- **`givesStepKeys`:** an exchange whose `given.stated` names a step writes every key that step gives (`STEP_GIVES`, from `A-S1.md` and `A-S2.md`), and its outcome wrote exactly the stated keys; a stated key beyond the step's own must be one an automatic step its walk passes gives (S1-11 after S1-02: arch 03 line 191). 02-contracts K-09: every journey 1 and 2 call writes the key its step gives.
